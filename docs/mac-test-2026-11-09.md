**Environment [MEAS]:** Matthew's MacBook Air, the browser pane inside the Claude desktop app, driven by Claude. User agent `Chrome/152.0.7977.167` (Claude/4.23118.1). This is **Chromium, not Safari**: it is real-hardware WebGPU evidence, not Safari acceptance, which stays **[USER-HW][OPEN]** (see [testing-provenance.md](./testing-provenance.md)).

**Build tested:** `main` at `c457a01`, release **1.8.31**, `exp7-platform/exp7-platform-lean.html` (2,549,471 chars). Fetched the launcher's way (public API, commit-pinned, no key) and its SHA-256 matched `release.json`. The page was written into an `https://example.com` tab with `document.write`, as the launcher does, so it ran in a secure context with a real origin.

## Calendar / Board / Plan [MEAS]

- **Paint:** Calendar, Board and Plan all paint on their GPU canvases at the column width (594 CSS px content in a ~596 px box after reveal).
- **Hits:** clicking day 13, then day 23, selected that day each time; `exp7views.calSel('vf-cal')` read `["2027-04-23"]` after the second click. Diagnostics counted the clicks.
- **Reveal on tab switch:** Board and Plan were correct on first visit. Calendar looked clipped at Thursday once, in a screenshot 1.5 s after opening it while the page was still finishing startup; after a fresh reload, and on every revisit, it was correct. **Not reproduced** — treat as a possible late reveal under startup load, not a confirmed bug.

### Bug: selection counter stays at 0 [MEAS]

After selecting a day, the calendar toolbar still draws **"0 day(s) selected"** although the selection state holds one day.

Cause (source of 1.8.31): a selection click goes through `calStateOnlyAsync` → `paintCalDayChrome`, which toggles `ja-sel` on the day cells and updates `V.calSelCount`, but does not rewrite the toolbar's `i.ja-dim` text. That text is only built by `calDoc` on a full rebuild. Fix belongs in `paintCalDayChrome` (rewrite the tip from `V.calSelCount`); it needs a release PR, so it is not fixed here.

## Parallax and frame time [MEAS]

- 6 `Exp7Slabs` controllers live. While the pointer moved across the Calendar for ~9 s, slabs drew 1,666 frames and applied 87 patches; `Exp7Slabs.errors` and `Exp7Motion.errors` stayed empty.
- Screenshots with the pointer at the top-left and then bottom-right of the Calendar show the day cells shift — parallax paints on this Mac.
- `requestAnimationFrame` intervals over the same run (550 frames): median 16.7 ms, p95 17.4 ms, p99 17.7 ms, max 17.8 ms, none over 20 ms. Steady 60 Hz with the pointer moving.
- Not measured: accessibility, large-data performance, device loss.
