## Runtime policy / renderer conflict
Only active, visible, non-reduced, non-form views run the explicitly requested ring ambient. Hidden/inactive/loading/drag phases pause without accumulating duplicate clocks or loops. No ambient RAF otherwise. Stable fronts/text are skipped on ambient frames. Original pointer/scroll paths produce <=1px front displacement, native hit geometry receives the same affine, and all original actions execute before visual scheduling. Authoring views rest while fields exist, keeping original hidden textarea/focus/IME coordinate ownership intact. The GPU canvas requires genuine native scene frames for visible ring animation; CSS compositor layers would replace/misalign the renderer, so none were added.
