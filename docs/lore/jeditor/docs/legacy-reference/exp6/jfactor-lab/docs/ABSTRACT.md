## Workshop abstract (~175 words)

Coding agents increasingly rely on **skills** (progressive procedure disclosure) and **MCP** (tool connectivity). These layers reduce *how much* procedure or catalog is loaded, but they do not decide *which process step is densest now*: what to open next, which child capability to enter for real I/O, or how to re-enter after reload without re-prefilling tools and docs. We present **JFactor Lab**, a study stack that places a densest **process kernel** (living-core) beside a coding **harness** (Grok Build) via MCP, driven by **JFactor/Exp6** ranking: sense → SimulatedBest → explore → Best (enter one). The kernel emits an attention-live **hop0** pack, a compact **handoff** for session re-enter, progressive **core** tools/list, debt-driven open_next, and a human **REVIEW** gate for money-bearing proposals. On a lab dump we measure hop0 ≈500 tok_est, handoff ≈75 tok (≈85% save vs hop0 text), and MCP core tools/list ≈753 tok (≈70% save vs full ≈2509). We argue contribution can proceed as open protocol and research even when upstream harnesses do not accept external monorepo PRs.

**Keywords:** coding agents · process ranking · hop0 · MCP · agent skills · progressive disclosure · JFactor · re-enter fidelity

## Bullet claims (reviewer scan)

3. hop0 + handoff beat catalog re-dump for re-enter.  
4. Core tools/list is a first-class context policy.  
5. Money actions need human gates (never invent $).  
6. Research contribution ≠ monorepo PR when upstream forbids external patches.
