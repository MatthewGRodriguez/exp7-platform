# 02 - Single animation runtime ("the binary")

Goal: one shared runtime (`jmotion`), inlined once into every level, with the training day designer (TDD) motion as the quality bar. Based on the real TDD engine, copied to `docs/legacy-reference/tdd-animation/` (authoritative workflow: `tdd_animation_workflow_from_artist.md`; engine: `06_web/sm_logic.js` 3,690 chars + `sm.css` 2,217 chars; state table `01_state/states.py`; `params.json`; parallax `10_px2b/`; caustics `03c_caustics/`; gates `07_qa/`).

## What the TDD engine is (as read)
- Not custom elements or shadow DOM: a small CSS+JS state machine. JS only sets a `data-sm` attribute plus `--sm-ms` / `--sm-ez` custom properties; CSS does all motion.
- Targets by selector (`.day-sched-block[data-ai], button, .ux-gh`); events delegated on document: pointerover/out/down/up, focusin/out (`:focus-visible`, try-guarded), click/keydown sync; MutationObserver maps the drag ghost's classes to states; `visibilitychange` toggles `html.sm-hid`.
- Element states: idle, hover, focus, pressed, selected, dragging, drop-pending, invalid, settling, disabled. App state on `html[data-sm-app]`: ready, apply-preview, undo.
- Poses per state (states.py): lift, tilt, scale, ring, opacity, e.g. hover lift 2, pressed scale .985, dragging lift 12 / scale 1.03 / gold ring, invalid = caution ring.
- Motion: individual `scale` / `translate` properties and pseudo-element opacity; two baked box-shadows (tight on `::before`, wide on `::after`, from Blender reads: offset 0.79 px and blur 0.93 px per px of lift) crossfaded.
- Edge timing table (`sm_art.txt`, key `from>to` -> [ms, easing index], fallback 120 ms), e.g. idle>hover 120, hover>idle 180, hover>pressed 60, pressed>dragging 160, dragging>drop-pending 80, settling>idle 260 overshoot, dragging>settling 240 (Escape glide-back), invalid>settling 360 overshoot (bounce back). Easings: `(.2,.8,.2,1)` out, `(.42,0,.58,1)` inout, `(.25,.1,.25,1)` soft, `(.3,1.3,.5,1)` overshoot, linear. Click-path edges <= 120 ms and never delay the action.
- Parallax (params.json `parallax`, PX2b): depth model with per-layer depth (platter -120, tiger -110, panel 0, inner 4, lifted 12 px), max offset 6 px, inputs pointermove + scroll (k 0.02); paused WAAPI animations with composite add scrubbed once per input frame (SM1b) and in PX2b inline translate + registered `--pr` written once per frame, MutationObserver primes new slabs. Off under reduced motion, hidden tab, loading.
- Ambient: slow drift of depth layers only (periods 31 s / 23 s, amp 4 / 3 px); glass lighting stays static, no looping shine (shine only to draw attention).
- Guards: no matchMedia -> treat reduced motion false; no `element.animate` -> skip WAAPI parallax; reduced motion -> all transitions/scale/translate off.
- Perf rules (measured): rAF only to coalesce input, none at idle; one running animation per property per element (two -> ~60 recalcs/s on main thread); do not restart per-element loops on re-render; drag p95 <= 16.8 ms and Apply <= 100 ms on the 1M-row page.

## Decisions (2026-10-30)
- Format: minified JS + CSS, inlined once into the level HTML; not WebAssembly (ADR 0001).
- Ambient drift: ON by default; per-level switch `motion.ambient.enabled` turns it off; still off under reduced motion, paused when hidden (ADR 0007).
- Build: the runtime is regenerated by a JEditor generator from the level's state table + params (poses, edge timing table, easings, parallax, ambient). Editing states/timings in the editor regenerates it. The TDD engine in `docs/legacy-reference/tdd-animation/` is the reference and parity target; the TDD quality gates (07_qa) check the generated output matches its motion (ADR 0004).

## JEditor runtime = this engine, generalized
- Same model: state attribute + edge table + CSS. Targets come from the level (component roots get `data-sm`) instead of a fixed selector.
- The edge table, poses, easings, parallax layers and ambient loops become data in the level JSON (`animations` / `motion` block, see 03), generated by the editor instead of by `gen_web.py`.
- Lighting numbers (shadow reads per px of lift) come from `params.json` / the pipeline's trace stage and are shipped as theme tokens; the pipeline (Blender/Moho on the Mac) stays the way to produce new lighting.
- Extras needed beyond SM1b for other apps: enter/exit, stagger reveal, FLIP move (TDD td.js already does these with WAAPI, delay 90 ms x index), value-change flash.
- Size: the TDD hand-typing limits (ASCII-only packed blocks, exact char counts, retype on edit) do NOT apply to JEditor's single-HTML output. The engine design, state table and QA gates DO apply.

## API sketch
```js
JMotion.install(levelMotionJSON)            // edge table, poses, easings, parallax, ambient
JMotion.go(el, 'hover')                     // set data-sm + --sm-ms/--sm-ez from edge table
JMotion.app('apply-preview')                // html[data-sm-app]
JMotion.play(el, 'enter' | 'exit' | 'flash', edits)
JMotion.stagger(els, 'enter', edits)
JMotion.flip(els, mutateFn, edits)
```

## Standard edits (editor panel on every animation)
| edit | applies to |
|---|---|
| state pose: lift, tilt, scale, ring, opacity | each state |
| edge duration (ms) and easing token | each `from>to` edge (click path capped at 120) |
| trigger | load, visible, click, hover, focus, state-change, value-change |
| delay, stagger (ms per item, order) | enter/exit/reveal |
| loop: off, count, infinite, alternate; period, amplitude | ambient drift (depth layers only) |
| parallax depth (px) per layer, on/off | layers |
| reduced-motion fallback: none, fade-only, instant | all |

## Embedding
Inlined once: `<style id="jmotion-css">` (generated from the level's motion data) + `<script id="jmotion" data-version data-hash>`. Components never ship animation code. Editor preview runs the same file.

## QA gates to keep (07_qa)
Click-path <= 120 ms; no rAF at idle; idle style recalcs ~0/s; no element with two running animations on one property; works without matchMedia; reduced motion = no motion; loops pause when hidden; text contrast >= 4.5 in every state; perf p95 <= 16.8 ms.

## Open questions
1. ANSWERED 2026-10-30: minified JS + CSS, not WebAssembly (ADR 0001).
2. ANSWERED 2026-10-30: regenerate from the state table + params via a JEditor generator; TDD engine is the parity target checked by its QA gates (ADR 0004).
3. Should JEditor levels keep the Blender/Moho lighting pipeline for new components, or reuse TDD's lighting numbers as fixed theme tokens?
4. ANSWERED 2026-10-30: ambient drift ON by default, per-level switch to turn it off (ADR 0007).
